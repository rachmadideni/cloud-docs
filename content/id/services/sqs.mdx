# SQS (Simple Queue Service)

**TL;DR**: Managed message queue. Decouple producer dari consumer. Pesan persist sampai consumer terima dan ack. Dua tipe: Standard (high-throughput, at-least-once) dan FIFO (ordered, exactly-once dengan deduplication).

## Analogi

Antrian bank. Nasabah taruh slip antrian (pesan), teller (consumer) ambil satu per satu. Tidak peduli nasabah datang serentak atau bertahap, teller proses sesuai kapasitas.

## Kapan pakai

- ✅ Decouple Lambda producer dari consumer (mis. publish event upload file, consumer process thumbnail).
- ✅ Buffer traffic burst supaya downstream tidak overwhelmed.
- ✅ Retry mechanism dengan dead letter queue (DLQ).
- ✅ Background job dispatch (kirim email, generate report).
- ✅ FIFO: order processing yang butuh urutan (mis. update inventory per SKU).

## Kapan jangan

- ❌ Real-time fanout ke banyak subscriber. Pakai SNS atau EventBridge.
- ❌ Stream processing dengan rewind capability. Pakai Kinesis.
- ❌ Sub-millisecond latency message passing. Pakai ElastiCache Redis pub/sub.
- ❌ Pesan besar dari 256 KB. Pakai S3 + SQS pointer.

## Standard vs FIFO

| Aspek | Standard | FIFO |
|---|---|---|
| Throughput | unlimited | 300 msg/detik (3000 dengan batching) |
| Ordering | best-effort | strict per MessageGroupId |
| Delivery | at-least-once (duplicate mungkin) | exactly-once dengan deduplication |
| Use case | high-throughput, idempotent consumer | banking, inventory, ordered events |
| Cost | $0.40 per 1M | $0.50 per 1M |

**Aturan praktis**: Standard untuk 95% use case. FIFO cuma kalau order beneran mandatory.

## Pricing mental model

| Komponen | Harga |
|---|---|
| Request | $0.40/1M (Standard), $0.50/1M (FIFO) |
| Free tier permanen | 1 juta request/bulan |
| Storage | gratis |
| Data transfer in-region | gratis |

Tagihan biasanya minor. Sticker shock cuma kalau pakai short polling instead of long polling (overhead empty receive call).

## Local emulator

**Floci status**: ✅ full (Standard + FIFO)

```bash
# Standard queue
awsl sqs create-queue --queue-name jobs

# FIFO queue (wajib suffix .fifo)
awsl sqs create-queue --queue-name orders.fifo \
  --attributes 'FifoQueue=true,ContentBasedDeduplication=true'
```

## Hello-world

```bash
QUEUE_URL=$(awsl sqs create-queue --queue-name demo \
  --query 'QueueUrl' --output text)

# Send
awsl sqs send-message --queue-url $QUEUE_URL \
  --message-body '{"task":"send-email","to":"alice@example.com"}'

# Receive (long polling 20 detik)
awsl sqs receive-message --queue-url $QUEUE_URL \
  --wait-time-seconds 20

# Delete setelah process (atau pesan re-deliver setelah visibility timeout)
awsl sqs delete-message --queue-url $QUEUE_URL \
  --receipt-handle "..."
```

Dari Lambda (auto-poll via event source mapping):

```bash
awsl lambda create-event-source-mapping \
  --function-name worker \
  --event-source-arn $QUEUE_ARN \
  --batch-size 10
```

Lambda otomatis poll, invoke handler dengan event berisi batch pesan, delete pesan kalau handler return success.

## Gotcha

- **At-least-once Standard**: pesan bisa di-deliver lebih dari sekali. Consumer harus **idempotent**. Pakai dedup key di handler.
- **Visibility timeout penting**: setelah `receive`, pesan jadi invisible selama X detik (default 30). Kalau process > visibility timeout, pesan re-appear, di-process double. Set timeout > max processing time, atau pakai `change-message-visibility` untuk extend.
- **Long polling > short polling**: set `wait-time-seconds 20` (max) di receive. Hemat API call, kurangi latency consume.
- **DLQ wajib di produksi**: tanpa DLQ, pesan yang gagal X kali stuck infinite retry. Setup `redrivePolicy` ke DLQ.
- **Message retention max 14 hari**: setelah itu auto-delete. Default 4 hari.
- **256 KB max message size**: untuk payload lebih besar (image, file), pakai S3 + send pointer ke SQS.
- **No native fanout**: 1 pesan = 1 consumer. Untuk broadcast, pakai SNS yang fanout ke multiple SQS.
- **FIFO MessageGroupId**: pesan dengan group sama strict ordered. Pesan dengan group beda paralel. Salah pilih MessageGroupId = throughput drop.
- **ContentBasedDeduplication**: dedup berdasarkan hash body. Pesan identik dalam 5 menit dianggap duplicate, di-skip. Bisa di-disable, pakai eksplisit `MessageDeduplicationId`.
- **Lambda batch failure handling**: kalau 1 dari 10 pesan fail, default seluruh batch fail dan re-deliver. Pakai `ReportBatchItemFailures` untuk partial fail.
