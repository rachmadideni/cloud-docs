# KMS (Key Management Service)

**TL;DR**: Managed encryption key. Generate, store, rotate, audit key tanpa pernah expose ke kamu. Pakai untuk encrypt S3, EBS, RDS, Secrets Manager, atau encrypt data app sendiri. Customer Managed Key (CMK) memberi kontrol lebih dari AWS-managed.

## Analogi

Brankas digital yang ada di basement AWS. Kamu kirim data, brankas encrypt pakai key di dalam (tidak pernah keluar). Mau decrypt, brankas yang lakukan, kasih hasil ke kamu.

## Kapan pakai

- ✅ Encrypt data at-rest di service AWS (S3, EBS, RDS, DynamoDB, Secrets).
- ✅ Encrypt secret/PII di aplikasi sendiri (envelope encryption).
- ✅ Digital signature dan verification (sign HTTP request, sign JWT).
- ✅ HMAC generation untuk MAC.
- ✅ Cross-account access control via key policy.
- ✅ Compliance requirement (audit log siapa decrypt apa kapan).
- ✅ Multi-region keys untuk DR.

## Kapan jangan

- ❌ Encrypt 100 MB file dengan KMS direct. Max payload Encrypt 4 KB. Pakai envelope encryption (KMS encrypt key kecil, key encrypt data besar).
- ❌ Performance-critical encryption high-throughput. Cache data key, jangan call KMS tiap request.
- ❌ Workload yang butuh export private key. KMS key tidak bisa di-export (good, tapi mungkin tidak fit).

## Jenis key

| Tipe | Use case | Control |
|---|---|---|
| **AWS-managed** | default untuk service AWS (`aws/s3`, `aws/rds`) | tidak bisa rotate/delete sendiri |
| **Customer-managed (CMK)** | recommended produksi | full control (rotation, policy, delete) |
| **AWS-owned** | service AWS pakai internal | invisible to you |
| **HMAC** | sign HMAC saja | symmetric |
| **Asymmetric** | sign/verify, encrypt dengan public key | RSA, ECC |
| **Multi-region** | replikasi key ke region lain | failover scenario |

Untuk produksi: pakai CMK customer-managed. Lebih kontrol, lebih audit-friendly.

## Local emulator

**Floci status**: ✅ full (sign + verify + encrypt + decrypt)

```bash
KEY_ID=$(awsl kms create-key \
  --description "App master key" \
  --query 'KeyMetadata.KeyId' --output text)

awsl kms create-alias \
  --alias-name alias/app-master \
  --target-key-id $KEY_ID

awsl kms enable-key-rotation --key-id $KEY_ID
```

## Hello-world

### Direct encrypt (untuk data kecil, di bawah 4 KB)

```bash
# Encrypt
CIPHERTEXT=$(awsl kms encrypt \
  --key-id alias/app-master \
  --plaintext "$(echo -n 'my-secret-token' | base64)" \
  --query CiphertextBlob --output text)

# Decrypt
awsl kms decrypt \
  --ciphertext-blob "$CIPHERTEXT" \
  --query Plaintext --output text | base64 -d
```

### Envelope encryption (untuk data besar)

```js
const { KMSClient, GenerateDataKeyCommand, DecryptCommand } =
  require('@aws-sdk/client-kms')
const crypto = require('crypto')

const kms = new KMSClient()

async function encryptLargeData(plaintext) {
  // 1. KMS generate data key (plain + encrypted)
  const { Plaintext: dataKey, CiphertextBlob: encryptedDataKey } =
    await kms.send(new GenerateDataKeyCommand({
      KeyId: 'alias/app-master',
      KeySpec: 'AES_256'
    }))

  // 2. Encrypt data dengan data key (local AES, cepat)
  const iv = crypto.randomBytes(12)
  const cipher = crypto.createCipheriv('aes-256-gcm', dataKey, iv)
  const encrypted = Buffer.concat([cipher.update(plaintext), cipher.final()])
  const tag = cipher.getAuthTag()

  // 3. Simpan encrypted data + encrypted data key + iv + tag
  return { encrypted, encryptedDataKey, iv, tag }
}

async function decryptLargeData({ encrypted, encryptedDataKey, iv, tag }) {
  // 1. KMS decrypt data key
  const { Plaintext: dataKey } = await kms.send(new DecryptCommand({
    CiphertextBlob: encryptedDataKey
  }))

  // 2. Decrypt data dengan data key
  const decipher = crypto.createDecipheriv('aes-256-gcm', dataKey, iv)
  decipher.setAuthTag(tag)
  return Buffer.concat([decipher.update(encrypted), decipher.final()])
}
```

Pattern envelope: KMS encrypt data key kecil (4 KB), data key encrypt data besar lokal pakai AES. Hemat cost API + cepat.

### Encrypt service AWS

S3 bucket:
```bash
aws s3 cp file.txt s3://bucket/ \
  --sse aws:kms --sse-kms-key-id alias/app-master
```

DynamoDB table:
```bash
aws dynamodb update-table --table-name Users \
  --sse-specification 'Enabled=true,SSEType=KMS,KMSMasterKeyId=alias/app-master'
```

## Gotcha

- **KMS key delete butuh 7-30 hari pending**: setelah delete, data yang di-encrypt key itu tidak bisa di-decrypt. Audit sebelum delete.
- **Key policy + IAM policy = AND**: principal butuh permission di KMS key policy AND IAM policy. Kalau cuma 1, tetap Deny.
- **Cross-account akses butuh dua-duanya**: key policy allow akun B, IAM di akun B allow user.
- **Rotation otomatis cuma backing material**: enable rotation bikin material baru tahunan, tapi key ID sama. Tidak bisa rotate manual (CreateKey baru = key ID baru).
- **GenerateDataKey return plain + encrypted**: plain ada di memory sebentar, harus zeroed setelah pakai. encrypted yang disimpan di disk.
- **Asymmetric key pakai padding scheme**: RSA OAEP atau PKCS1v15. Mismatch antara sign dan verify = invalid signature.
- **Cross-region encryption butuh Multi-Region Key**: standard key region-locked. Untuk fail-over multi-region, pakai MRK.
- **External key store (XKS)**: pakai HSM kamu sendiri sebagai backing key. Cost lebih mahal, untuk compliance ketat.
- **Encryption context untuk additional auth data**: pass `EncryptionContext: { user_id: 'abc' }` saat encrypt. Decrypt wajib context sama. Defense tambahan.
