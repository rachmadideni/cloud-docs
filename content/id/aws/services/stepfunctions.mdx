# Step Functions

**TL;DR**: State machine serverless untuk orchestrate workflow. Definisikan flow via JSON (ASL, Amazon States Language). State persisted, retry/catch declarative, parallel branch native. Pakai untuk workflow lebih dari 3 step yang butuh state atau error handling.

## Analogi

Diagram flowchart yang beneran jalan. Setiap kotak adalah state (panggil Lambda, query DynamoDB, wait), panah adalah transition.

## Kapan pakai

- ✅ Multi-step workflow yang butuh persist state (mis. order fulfillment: validate -> charge -> ship -> notify).
- ✅ Workflow lebih dari 15 menit (Lambda limit). Standard support sampai 1 tahun.
- ✅ Need retry declarative dengan exponential backoff per step.
- ✅ Parallel branch (panggil 5 API bersamaan, tunggu semua selesai).
- ✅ Wait for callback (workflow pause sampai external system kasih signal).
- ✅ Visual debug di console (lihat eksekusi step by step).
- ✅ Human approval workflow (pause, kirim email, lanjut setelah approver klik).

## Kapan jangan

- ❌ Workflow simpel 2 step. Lambda chain langsung lebih murah.
- ❌ Real-time per-request latency-sensitive. Step Functions add overhead.
- ❌ Workflow ribuan execution/detik high-throughput. Cost transition mahal.

## Standard vs Express

| Aspek | Standard | Express |
|---|---|---|
| Duration | sampai 1 tahun | max 5 menit |
| State persist | iya | tidak (memory only) |
| Pricing | $25/1M state transition | $1/1M + duration |
| Use case | long workflow, audit needed | high-throughput, event processing |
| Execution visible di console | tabel + timeline | terbatas |

**Aturan praktis**: Express untuk workflow pendek high-volume (90% lebih murah). Standard untuk long-running atau audit-critical.

## Pricing mental model

| Komponen | Standard | Express |
|---|---|---|
| State transition | $25 per 1M | $1 per 1M |
| Duration | gratis | $0.00001667/GB-second (mirip Lambda) |
| Plus target service cost | Lambda, DynamoDB, dll | sama |

Workflow 10 step × 100k execution = 1M transition = $25 (Standard) vs $1 + $0.50 duration = $1.50 (Express).

## Local emulator

**Floci status**: ✅ full (ASL support)

```bash
# State machine simpel
cat > workflow.json << 'EOF'
{
  "StartAt": "Hello",
  "States": {
    "Hello": {
      "Type": "Pass",
      "Result": "Hello World",
      "End": true
    }
  }
}
EOF

awsl stepfunctions create-state-machine \
  --name hello-sm \
  --definition file://workflow.json \
  --role-arn arn:aws:iam::000000000000:role/sfn-role

awsl stepfunctions start-execution --state-machine-arn arn:... \
  --input '{}'
```

## Hello-world (workflow real)

Order fulfillment dengan retry plus catch:

```json
{
  "Comment": "Order fulfillment",
  "StartAt": "Charge",
  "States": {
    "Charge": {
      "Type": "Task",
      "Resource": "arn:aws:lambda:us-east-1:000000000000:function:charge",
      "Retry": [{
        "ErrorEquals": ["States.TaskFailed"],
        "IntervalSeconds": 2,
        "MaxAttempts": 3,
        "BackoffRate": 2.0
      }],
      "Catch": [{
        "ErrorEquals": ["States.ALL"],
        "Next": "MarkFailed"
      }],
      "Next": "Ship"
    },
    "Ship": {
      "Type": "Pass",
      "Result": { "tracking": "FX-123" },
      "ResultPath": "$.shipping",
      "Next": "UpdateDB"
    },
    "UpdateDB": {
      "Type": "Task",
      "Resource": "arn:aws:states:::dynamodb:updateItem",
      "Parameters": {
        "TableName": "Orders",
        "Key": { "id": { "S.$": "$.orderId" } },
        "UpdateExpression": "SET #s=:s",
        "ExpressionAttributeNames": { "#s": "status" },
        "ExpressionAttributeValues": { ":s": { "S": "fulfilled" } }
      },
      "End": true
    },
    "MarkFailed": {
      "Type": "Pass",
      "End": true
    }
  }
}
```

Service integration langsung (`arn:aws:states:::dynamodb:updateItem`) hemat cost karena tidak perlu Lambda perantara.

## State type penting

| Type | Fungsi |
|---|---|
| **Task** | panggil resource (Lambda, AWS service, activity worker) |
| **Pass** | data transformation tanpa side-effect |
| **Choice** | branch berdasarkan kondisi input |
| **Wait** | delay (detik fixed atau timestamp) |
| **Parallel** | jalankan beberapa branch bersamaan, tunggu semua |
| **Map** | iterate array, jalankan workflow per item |
| **Succeed** | end success |
| **Fail** | end failure dengan error |

## Gotcha

- **Input/output max 256 KB**: untuk data besar, simpan di S3, kirim S3 key lewat workflow.
- **Lambda invoke = double cost**: Task panggil Lambda kena cost Step Functions transition + Lambda invocation. Untuk simple API call, pakai service integration langsung.
- **JSONPath `$.field` vs literal**: kalau pakai variable dari input, suffix `.$`: `"S.$": "$.orderId"`. Tanpa `.$`, dianggap literal string.
- **Express tidak punya history execution di console**: harus rely on CloudWatch Logs. Set `LoggingConfiguration` saat create.
- **Standard execution unique name 90 hari**: nama execution tidak bisa di-reuse selama 90 hari setelah completion. Pakai UUID atau timestamp.
- **Wait state Wall-clock charged**: workflow yang Wait 1 hari = bayar 1 hari Standard execution. Express tidak cocok untuk Wait panjang.
- **Map state max 10k iteration**: untuk array lebih besar, pakai Distributed Map (sub-fitur, support sampai 100k iteration).
- **Callback pattern dengan `.waitForTaskToken`**: workflow pause, generate token, external system harus call `SendTaskSuccess/Failure` dengan token. Timeout default 1 jam.
- **Service integration sync vs async**: `.sync` wait untuk service complete, `.waitForTaskToken` wait token, no suffix = fire-and-forget.
- **Tidak ada loop native**: untuk loop, pakai Choice yang transition balik ke state sebelumnya. Iterasi banyak pakai Map.
