# Glue

**TL;DR**: Serverless ETL service + Data Catalog. Crawler scan source data, infer schema, populate metadata catalog. ETL job (PySpark/Scala/Python) transform data. Athena, Redshift, EMR baca dari Data Catalog yang sama.

## Analogi

Pustakawan otomatis untuk data lake. Sortir buku (data file), bikin katalog (schema metadata), bersihkan dan reformat (ETL job).

## Kapan pakai

- ✅ Bikin metastore untuk Athena/Redshift Spectrum query S3.
- ✅ Crawl folder S3, auto-detect schema, register sebagai table.
- ✅ ETL job: transform CSV ke Parquet, join multiple source, cleanse data.
- ✅ Schema registry untuk streaming pipeline (Kafka, Kinesis).
- ✅ Data lineage tracking via Glue DataBrew (no-code).
- ✅ Incremental crawl (cuma scan partition baru).

## Kapan jangan

- ❌ Pipeline simpel (drop file ke S3, query Athena). Skip crawler, definisikan table manual.
- ❌ Real-time transformation. Pakai Lambda atau Kinesis Analytics.
- ❌ Sub-detik latency. Spark cold start beberapa puluh detik.
- ❌ Volume kecil (di bawah GB). Cost minimum job tidak worth.

## Komponen

| Term | Fungsi |
|---|---|
| **Data Catalog** | metastore (database, table, partition definition) |
| **Crawler** | scan source, infer schema, update catalog |
| **Job** | ETL script (PySpark/Scala/Python), schedule-able |
| **Trigger** | start job berdasarkan event atau cron |
| **Workflow** | orkestrasi multiple job + crawler |
| **DataBrew** | no-code data prep UI |
| **Schema Registry** | versioned schema untuk Kafka/Kinesis |

## Pricing mental model

| Komponen | Harga |
|---|---|
| Data Catalog | 100k object gratis/bulan, $1/100k setelah |
| Crawler | $0.44 per DPU-hour |
| Job (Spark) | $0.44 per DPU-hour (G.1X, default) |
| Job (Python shell) | $0.44 per DPU-hour |
| DataBrew | $1.00 per node-hour |
| Schema Registry | gratis untuk 1M operation/bulan |

1 DPU = 4 vCPU + 16 GB RAM. Job standard 10 DPU × 30 menit = 5 DPU-hour = $2.20.

## Local emulator

**Floci status**: ✅ full (catalog + crawler basic)

```bash
# Database
awsl glue create-database --database-input Name=analytics

# Table manual (tanpa crawler)
awsl glue create-table --database-name analytics --table-input '{
  "Name": "events",
  "TableType": "EXTERNAL_TABLE",
  "PartitionKeys": [{"Name":"day","Type":"string"}],
  "StorageDescriptor": {
    "Columns": [{"Name":"user_id","Type":"string"},{"Name":"action","Type":"string"}],
    "Location": "s3://data-lake/events/",
    "InputFormat": "org.apache.hadoop.hive.ql.io.parquet.MapredParquetInputFormat",
    "OutputFormat": "org.apache.hadoop.hive.ql.io.parquet.MapredParquetOutputFormat",
    "SerdeInfo": {
      "SerializationLibrary": "org.apache.hadoop.hive.ql.io.parquet.serde.ParquetHiveSerDe"
    }
  }
}'
```

## Hello-world

### Crawler (auto-discover schema)

```bash
awsl glue create-crawler \
  --name events-crawler \
  --role arn:aws:iam::000000000000:role/glue-role \
  --database-name analytics \
  --targets '{"S3Targets":[{"Path":"s3://data-lake/events/"}]}'

awsl glue start-crawler --name events-crawler

# Lihat schema yang di-detect
awsl glue get-tables --database-name analytics
```

### ETL Job (PySpark example)

```python
# transform.py
import sys
from awsglue.utils import getResolvedOptions
from awsglue.context import GlueContext
from pyspark.context import SparkContext

args = getResolvedOptions(sys.argv, ['JOB_NAME'])
sc = SparkContext()
gc = GlueContext(sc)

# Read source
src = gc.create_dynamic_frame.from_catalog(
    database='analytics', table_name='events_raw'
)

# Transform
clean = src.filter(lambda row: row['user_id'] is not None)
clean = clean.apply_mapping([
    ('user_id', 'string', 'userId', 'string'),
    ('action', 'string', 'eventType', 'string'),
    ('ts', 'long', 'timestamp', 'long')
])

# Write Parquet ke S3
gc.write_dynamic_frame.from_options(
    frame=clean,
    connection_type='s3',
    connection_options={'path': 's3://data-lake/events-clean/'},
    format='parquet'
)
```

Upload script ke S3, create job:

```bash
awsl s3 cp transform.py s3://my-scripts/

awsl glue create-job \
  --name clean-events \
  --role arn:aws:iam::000000000000:role/glue-role \
  --command 'Name=glueetl,ScriptLocation=s3://my-scripts/transform.py,PythonVersion=3' \
  --glue-version "4.0" \
  --number-of-workers 2 \
  --worker-type G.1X

awsl glue start-job-run --job-name clean-events
```

## Gotcha

- **Crawler bisa miss schema kalau JSON nested kompleks**: array of object atau deeply nested susah diinfer. Definisikan table manual untuk schema kompleks.
- **Crawler bikin table per "folder"**: kalau path `s3://bucket/events/2024/` dan `s3://bucket/events/2025/`, crawler bisa anggap 2 table. Pakai `TableLevelConfiguration` untuk control.
- **Partition projection alternatif crawler**: untuk partition predictable (year/month/day), enable partition projection di table properties. Athena generate partition dari config, tidak perlu crawler scan.
- **Job startup time 1-3 menit**: Spark cluster cold start. Pakai Glue Job G.025X (Auto Scaling) atau Glue Interactive Sessions untuk dev iteration cepat.
- **DPU minimum**: G.1X minimum 2 worker = 2 DPU. Job kecil bayar overhead.
- **Bookmark untuk incremental**: enable bookmark supaya job cuma proses data baru sejak last run. Tanpa bookmark, full scan tiap run = mahal.
- **Glue version vs Spark version**: pin Glue version (3.0, 4.0). Migrate antar version bisa break dependency PySpark.
- **Schema evolution**: kolom baru di source = crawler update schema, tapi table sudah ada cuma append schema (kolom baru di akhir). Reorder schema = bikin table baru.
- **Cross-account catalog access**: bisa share Data Catalog antar akun via resource policy. Setup ribet.
- **Catalog vs Lake Formation**: Lake Formation adalah layer permission di atas Glue Catalog. Bisa coexist tapi konfusing. Pilih satu approach.
