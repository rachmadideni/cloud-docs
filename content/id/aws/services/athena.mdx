# Athena

**TL;DR**: Serverless SQL engine untuk query data di S3. Tanpa cluster, tanpa indexing, tanpa setup. Bayar per data scanned ($5/TB). Pakai untuk ad-hoc analytics di data lake.

## Analogi

SQL terminal yang langsung query file di Google Drive. Tidak perlu load ke database dulu. File CSV, JSON, Parquet, ORC, semua bisa di-query.

## Kapan pakai

- ✅ Ad-hoc analytic query di data lake S3.
- ✅ Log analysis: query CloudTrail, ELB log, VPC Flow Logs.
- ✅ Reporting: aggregate jutaan record dengan SQL standar.
- ✅ Cost monitoring: query Cost and Usage Report di S3.
- ✅ One-time data exploration tanpa setup database.
- ✅ Federated query: gabung data S3 + RDS + DynamoDB dalam 1 query (via Federated Query connector).

## Kapan jangan

- ❌ OLTP workload (insert, update, delete per row). Pakai RDS/DynamoDB.
- ❌ Latency sub-detik. Athena query latency 2-30 detik.
- ❌ High concurrency (>20 query bersamaan). Pakai Redshift Serverless.
- ❌ Complex BI dashboard dengan banyak refresh. Bisa, tapi cost scan naik cepat.
- ❌ Iterative dev cycle. Scan cost bikin debug mahal. Sample data dulu di local DuckDB.

## Pricing mental model

| Komponen | Harga |
|---|---|
| Per query | $5 per TB scanned |
| DDL (CREATE/DROP table) | gratis |
| Failed/cancelled query | gratis (kecuali yang sudah scan) |
| Provisioned capacity (workgroup) | $0.30 per DPU-hour, tidak per-scan |

Optimisasi cost:
- **Parquet/ORC instead of JSON/CSV**: 10x lebih kecil = 10x lebih murah scan.
- **Partition pruning**: query `WHERE day = '2026-05-27'` cuma scan 1 folder.
- **Column projection**: `SELECT col1, col2` bukan `SELECT *`. Columnar format cuma baca kolom yang diminta.
- **Compression** built-in di Parquet (Snappy default).

Contoh: 1 query `SELECT * FROM events WHERE day='2026-05-27'` di table 100 GB Parquet partitioned by day, 1 day = 100 MB. Scan 100 MB = $0.0005.

## Local emulator

**Floci status**: ✅ full (backend DuckDB), Floci-exclusive vs LocalStack Free

Athena di Floci pakai DuckDB sebagai engine. Query SQL beneran jalan, result keluar. Setup butuh table di Glue Catalog dulu.

```bash
# Bikin workgroup result location
awsl s3 mb s3://athena-results

# Run query
QID=$(awsl athena start-query-execution \
  --query-string "SELECT page, COUNT(*) FROM analytics.events GROUP BY page LIMIT 10" \
  --result-configuration "OutputLocation=s3://athena-results/" \
  --query 'QueryExecutionId' --output text)

sleep 3

awsl athena get-query-results --query-execution-id $QID --output table
```

## Hello-world

### Setup table virtual

```sql
-- Bikin database
CREATE DATABASE analytics;

-- Bikin table point ke S3
CREATE EXTERNAL TABLE analytics.events (
  user_id STRING,
  page STRING,
  ts BIGINT
)
PARTITIONED BY (day STRING)
STORED AS PARQUET
LOCATION 's3://data-lake/events/';

-- Discover partition (kalau partition path conform Hive)
MSCK REPAIR TABLE analytics.events;
```

### Query analytic

```sql
-- Top page per hari
SELECT day, page, COUNT(*) AS views
FROM analytics.events
WHERE day BETWEEN '2026-05-01' AND '2026-05-31'
GROUP BY day, page
ORDER BY day, views DESC;

-- Unique user
SELECT day, COUNT(DISTINCT user_id) AS uu
FROM analytics.events
WHERE day = '2026-05-27'
GROUP BY day;

-- Funnel
WITH sessions AS (
  SELECT user_id, array_agg(page ORDER BY ts) AS path
  FROM analytics.events
  WHERE day = '2026-05-27'
  GROUP BY user_id
)
SELECT
  SUM(CASE WHEN contains(path, '/home') THEN 1 ELSE 0 END) AS step1,
  SUM(CASE WHEN contains(path, '/product') THEN 1 ELSE 0 END) AS step2,
  SUM(CASE WHEN contains(path, '/checkout') THEN 1 ELSE 0 END) AS step3
FROM sessions;
```

## Gotcha

- **MSC REPAIR mahal di partition banyak**: untuk table dengan ribuan partition, MSC REPAIR scan semua. Pakai `ALTER TABLE ADD PARTITION` manual atau partition projection.
- **Partition projection lebih cepat dari crawler**: enable di table properties, Athena generate partition dari konfigurasi. Skip Glue crawler.
- **Query result di S3**: setiap query bikin file CSV result di S3 (location yang di-set di workgroup). Lifecycle policy untuk cleanup, atau jadi cost storage diam-diam.
- **Workgroup wajib produksi**: tanpa workgroup, query default ke `primary`. Workgroup terpisah untuk dev/staging/prod dengan cost guard `BytesScannedCutoffPerQuery`.
- **Athena 30 menit timeout per query**: query lama harus pakai EMR atau Redshift. Atau optimize.
- **CREATE TABLE AS SELECT (CTAS)**: bikin table baru sambil transform. Hasil di S3 sebagai Parquet otomatis. Hemat di-baca berkali-kali.
- **Iceberg / Hudi format**: support ACID operation (UPDATE, DELETE, MERGE) di S3. Untuk slowly changing dimension. Setup Iceberg via Glue Catalog.
- **Federated query mahal**: panggil RDS/DynamoDB lewat Athena = invoke Lambda connector + cost per scan. Untuk query lintas-source frequent, ETL ke S3 dulu.
- **EXPLAIN dulu untuk query mahal**: EXPLAIN ANALYZE show statistik scan. Sebelum run di production scale, EXPLAIN dulu di sample data.
- **Reserved keyword conflict**: kolom dengan nama `timestamp`, `date`, `order` harus quoted (`"timestamp"`). Hindari pakai reserved word di schema.
