# Secrets Manager

**TL;DR**: Managed secret storage. Simpan password DB, API key third-party, certificate. Auto-rotation untuk RDS, encryption via KMS, audit via CloudTrail. Ganti naro secret di env var atau commit ke git.

## Analogi

Brankas khusus untuk secret app. Lambda atau ECS task fetch saat runtime, tidak ada secret di disk atau env var.

## Kapan pakai

- ✅ Password database (RDS) dengan rotation otomatis.
- ✅ API key third-party (Stripe, Twilio, OpenAI).
- ✅ JWT signing key.
- ✅ Webhook secret (verify signature dari third-party).
- ✅ OAuth client secret.
- ✅ Cross-account secret sharing via resource policy.
- ✅ Compliance audit (siapa fetch secret kapan).

## Kapan jangan

- ❌ Config non-secret (feature flag, URL endpoint). Pakai Parameter Store (gratis).
- ❌ Public key, non-sensitive metadata. Pakai Parameter Store.
- ❌ High-throughput read tanpa cache. $0.05 per 10k API call.
- ❌ Encrypt large blob (>64 KB). Pakai S3 + KMS envelope.

## Secrets Manager vs Parameter Store

| Aspek | Secrets Manager | Parameter Store |
|---|---|---|
| Cost per secret | $0.40/bulan | gratis (standard tier) |
| Cost per API call | $0.05/10k | gratis (standard) |
| Auto-rotation | iya (Lambda-based) | tidak |
| Cross-account | iya (resource policy) | tidak native |
| Max size | 64 KB | 4 KB (standard), 8 KB (advanced $0.05/param) |
| Use case | true secret dengan rotation | config + secret hybrid |

Aturan praktis: **Secrets Manager** untuk credential yang butuh rotation atau compliance. **Parameter Store SecureString** untuk static credential atau config.

## Pricing mental model

| Komponen | Harga |
|---|---|
| Per secret | $0.40/bulan |
| Per 10k API call | $0.05 |
| Encryption (KMS) | $1/CMK/bulan + $0.03/10k API |

10 secret × $0.40 = $4/bulan. Plus call cost negligible untuk app normal.

Tagihan kaget: Lambda yang fetch secret tiap invocation tanpa cache. 1M invoke × $0.05/10k = **$5/bulan per secret per Lambda**. Cache di module scope.

## Local emulator

**Floci status**: ✅ full

```bash
awsl secretsmanager create-secret \
  --name app/prod/db \
  --secret-string '{"username":"app","password":"strong-pass","host":"db.example.com"}'

awsl secretsmanager get-secret-value --secret-id app/prod/db
```

## Hello-world

### Lambda fetch dengan cache

```js
const { SecretsManagerClient, GetSecretValueCommand } =
  require('@aws-sdk/client-secrets-manager')

const sm = new SecretsManagerClient()
let cached = null  // module scope, persist antar warm invocation

async function getSecret() {
  if (cached) return cached
  const res = await sm.send(new GetSecretValueCommand({
    SecretId: 'app/prod/db'
  }))
  cached = JSON.parse(res.SecretString)
  return cached
}

exports.handler = async () => {
  const creds = await getSecret()
  // pakai creds.username, creds.password
}
```

### Auto-rotation untuk RDS

```bash
awsl secretsmanager rotate-secret \
  --secret-id app/prod/db \
  --rotation-lambda-arn arn:aws:lambda:us-east-1:000000000000:function:SecretsManagerRDSRotation \
  --rotation-rules AutomaticallyAfterDays=30
```

Lambda yang AWS provide handle rotation: bikin password baru, update RDS, update secret value, test koneksi. Tanpa downtime karena RDS support dual password sementara.

## Gotcha

- **Cache di module scope**: fetch tiap invocation = mahal. Cache di luar handler, refresh saat secret rotated (catch authentication error, refresh, retry).
- **Rotation Lambda butuh VPC access kalau DB di private subnet**: setup VPC + NAT (untuk Lambda akses Secrets Manager API).
- **Rotation breaks app tanpa dual-credential pattern**: kalau app tidak handle rotation (cache lama, password sudah rotated), authentication fail. RDS support dual password sementara via rotation Lambda.
- **Delete secret tidak instant**: minimum 7 hari recovery window (force-delete-without-recovery untuk dev only).
- **Secret name unique per region per akun**: tidak global.
- **Replication ke region lain**: enable replica untuk DR. Cost storage tambahan per region.
- **Encryption pakai aws/secretsmanager default**: aman tapi cuma encryption-at-rest. Pakai CMK customer-managed untuk audit lebih ketat.
- **Resource policy untuk cross-account**: principal di akun lain butuh allow di policy secret + IAM policy di akun itu.
- **Cost ribuan secret = mahal**: untuk app dengan ribuan tenant credential, pertimbangkan custom encryption di DynamoDB + KMS (lebih murah).
- **JSON parsing wajib**: secret value adalah string. App harus parse JSON. Format konsisten antar environment.
