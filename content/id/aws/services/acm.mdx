# ACM (AWS Certificate Manager)

**TL;DR**: Issue dan kelola sertifikat SSL/TLS gratis untuk domain kamu. Auto-renew, deep integration ke CloudFront, ALB, API Gateway. Zero cost untuk domain yang di-host AWS.

## Analogi

Certificate authority pribadi untuk akun AWS. Gantikan beli SSL cert dari third-party ($50-500/tahun) plus manual renew tiap tahun.

## Kapan pakai

- ✅ HTTPS untuk CloudFront distribution.
- ✅ HTTPS untuk ALB atau NLB.
- ✅ HTTPS untuk API Gateway custom domain.
- ✅ HTTPS untuk Elastic Beanstalk environment.
- ✅ Wildcard cert (`*.example.com`) untuk subdomain dynamic.

## Kapan jangan

- ❌ Cert untuk server di luar AWS. ACM cert tidak bisa di-export.
- ❌ EV (Extended Validation) cert dengan green bar di browser. ACM cuma DV (Domain Validation).
- ❌ Client cert untuk mutual TLS authentication. Pakai ACM Private CA atau third-party.

## Pricing mental model

| Komponen | Harga |
|---|---|
| Public ACM cert | gratis |
| Auto-renew | gratis |
| Private CA (ACM PCA) | $400/bulan per CA + $0.75 per cert (mahal!) |

Untuk 99% use case (public website + API), gratis total.

## Local emulator

**Floci status**: ✅ full (REST JSON)

```bash
awsl acm request-certificate \
  --domain-name example.com \
  --validation-method DNS
```

Validation di Floci di-auto-approve. Di AWS asli butuh tambah DNS record (otomatis kalau pakai Route53).

## Hello-world

Request cert untuk domain di AWS asli:

```bash
CERT_ARN=$(aws acm request-certificate \
  --domain-name api.example.com \
  --subject-alternative-names "*.api.example.com" \
  --validation-method DNS \
  --query CertificateArn --output text)

# Lihat DNS validation record yang harus ditambahkan
aws acm describe-certificate --certificate-arn $CERT_ARN \
  --query 'Certificate.DomainValidationOptions[].ResourceRecord'
```

Tambahkan CNAME record yang di-output ke DNS. Tunggu beberapa menit untuk validation.

Kalau zone di Route53, lebih simpel:

```bash
# Auto-validate via Route53
aws acm request-certificate \
  --domain-name api.example.com \
  --validation-method DNS \
  --domain-validation-options DomainName=api.example.com,ValidationDomain=example.com
```

Plus ACM akan minta untuk insert validation record ke Route53. Setelah validasi sukses, cert ready dipakai.

## Gotcha

- **Region-scoped, kecuali CloudFront**: cert untuk ALB di `ap-southeast-3` harus di-create di `ap-southeast-3`. Untuk CloudFront, cert **harus di us-east-1**, no exception.
- **DNS validation lebih reliable dari email**: kalau pilih email validation, AWS kirim email ke `admin@`, `administrator@`, `hostmaster@`, `webmaster@`, `postmaster@`. Banyak yang miss karena email forward atau spam folder. Pakai DNS validation.
- **Auto-renew butuh validation record tetap ada**: kalau hapus CNAME validation setelah cert terbit, renew di tahun berikutnya fail. Biarkan record itu permanen.
- **Wildcard cert tidak cover apex**: `*.example.com` cover `api.example.com`, `www.example.com`, tapi tidak cover `example.com`. Tambahkan SAN `example.com` di request.
- **Cert maximum 100 SAN per cert**: untuk domain lebih banyak, bikin cert terpisah.
- **Tidak bisa export private key**: cert ACM stick di AWS. Server di luar AWS pakai cert lain (Let's Encrypt gratis).
- **Pending validation expire 72 jam**: kalau validation record belum di-add dalam 72 jam, request kena cancel.
- **Cert dengan resource attached tidak bisa dihapus**: detach dari CloudFront/ALB dulu.

## Cross-provider

| Provider | Service | Catatan |
|---|---|---|
| Azure | Key Vault Certificates | manage cert, bukan issue (integrasi ke CA seperti DigiCert) |
| GCP | Certificate Manager | gratis untuk Google-managed cert |
| Oracle | OCI Certificates | gratis untuk public cert |
| Third-party | Let's Encrypt | gratis, manual renew via certbot |
